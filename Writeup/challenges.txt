# Phase 0 - Define the Scope and Success Criteria

1. Challenge: The terminal did not interpret the project path correctly.
Context: I tried to navigate to the project directory using its full path without quotes. The path contained spaces and a closing parenthesis in 1)Projects.
Description: zsh interpreted the spaces as argument separators and the unquoted parenthesis as shell syntax, so the command did not reach the intended directory.
How I fixed it: I enclosed the entire path in single quotes:

cd '/Users/naman/1)Projects/agentic AI projects/Autonomous-ML-Production-Monitoring-and-Recovery-Agent'

Lesson learned: I needed to quote full paths containing spaces or shell-special characters, including file paths passed to commands.

2. Challenge: The empty component directories did not appear in Git.
Context: I created the initial folders for the agent, backend, ML service, retrieval, and other components before adding implementation files. The empty folders did not appear in git status.
Description: Git tracked files rather than empty directories, so creating a folder alone did not preserve it in the repository.
How I fixed it: I added a .gitkeep file to each empty component directory. For example:

touch agent/graph/.gitkeep

Lesson learned: I used placeholder files to preserve the initial directory structure. The .gitkeep name was a convention, not a special Git feature.

3. Challenge: steps.txt remained tracked after I added it to .gitignore.
Context: I wanted Writeup/steps.txt to stay on my computer without being included in future commits, but the file had already been added to Git.
Description: The /steps.txt rule matched only a file at the repository root. Also, ignore rules did not remove a file that was already in the Git index.
How I fixed it: I changed the rule to steps.txt so it matched at every directory level, then removed the writeup from the index while preserving the local file:

git rm --cached -- Writeup/steps.txt
git check-ignore Writeup/steps.txt

The ignore check printed Writeup/steps.txt. Git showed a staged deletion because the next commit needed to remove the tracked copy; the local file remained intact.

Lesson learned: I needed both a matching ignore rule and removal from the index to stop tracking an existing file. I used --cached to retain the local copy.

4. Challenge: A multiline editing command failed with an unmatched quote.
Context: I used a shell heredoc to run a Python editing script. The text being written to steps.txt included another heredoc command with the same PY terminator.
Description: The shell treated the inner PY line as the end of the outer script. It then parsed the remaining document text as shell input and reported an unmatched quote before the editing script ran.
How I fixed it: I changed the outer terminator to PHASE0_SCRIPT, kept PY for the command inside the document, and reran the editing command. Both closing terminators were placed on their own lines without indentation.
Lesson learned: I needed distinct delimiters when a heredoc contained another heredoc example.

# Phase 1 - Build the Baseline ML Production System

1. Challenge: The HTTP test client emitted a deprecation warning.
Context: I ran the small API tests with the pinned FastAPI and Starlette packages and the original HTTPX development dependency.
Description: Starlette reported that its TestClient integration with httpx was deprecated and identified httpx2 as the supported replacement. The tests passed, but the dependency choice left the warning in every test run.
How I fixed it: I replaced the HTTPX entry in requirements-dev.txt with the compatible pinned HTTPX2 client, installed it in the isolated test environment, and reran the tests.
Lesson learned: I checked the test client's dependency requirements alongside the framework version rather than assuming that older testing examples still matched the installed framework.

2. Challenge: A missing model bundle made prediction and readiness requests return HTTP 503.
Context: I exercised startup with an empty artifact directory in the small integration tests.
Description: No metadata.json or trained estimator existed for the selected model version. A running FastAPI process alone did not make the prediction service ready.
How I fixed it: I separated liveness from readiness, recorded the loading failure, and kept predictions unavailable until a valid bundle could be loaded. I put data generation and training before startup in the local execution steps; the application did not train implicitly.
Lesson learned: I needed to check /health/ready and model artifacts rather than using process liveness as proof that inference worked.

3. Challenge: Changed artifacts and incompatible metadata prevented model loading.
Context: I exercised checksum, feature-order, and runtime-version mismatches in the artifact-loading tests.
Description: A model file could not safely be treated as interchangeable with any dataset, preprocessing order, or scikit-learn environment. The loader rejected those mismatches before deserialization.
How I fixed it: I recorded the shared contract, bundle checksums, and exact training-library versions in metadata, pinned the runtime dependencies, and made startup validate them. The rejection tests passed without loading the invalid model.
Lesson learned: I needed the model's input contract and compatible environment alongside the serialized estimator. A checksum established integrity, while the source directory still needed to be trusted.
